# Contributing to Signal Processing Toolkit

Thank you for considering contributing to this project! This document outlines the process for contributing.

## How to Contribute

1. Fork the repository
2. Create a new branch for your feature or bug fix
3. Make your changes
4. Ensure your code follows the existing style
5. Add tests for new functionality
6. Run the test suite to ensure nothing is broken
7. Submit a pull request

## Code Style

- Follow PEP 8 for Python code
- Use descriptive variable and function names
- Add docstrings to all public functions
- Include type hints where beneficial
- Keep functions focused and modular

## Testing

- Write tests using pytest
- Place tests in the `tests/` directory
- Aim for high test coverage
- Tests should be deterministic and fast

## Documentation

- Update docstrings when modifying functions
- Add examples to the `examples/` directory for new features
- Update this contributing guide if processes change

## Reporting Issues

Please use the GitHub issue tracker to report bugs or request features. Include:
- Clear description of the issue
- Steps to reproduce (if applicable)
- Expected vs actual behavior
- Environment details (Python version, OS, etc.)
